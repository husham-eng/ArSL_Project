# بروتوكول الاختبار الميداني للمتطوعين

هذا البروتوكول يستجيب مباشرة لملاحظة المحكمين بخصوص محدودية الاختبار الحي
السابق (تجربة واحدة فقط، `n=1`، Section 4.6 / Section 6 من الورقة). يستخدم
**"وضع الاختبار الميداني"** المضاف حديثًا لتطبيق `practice_session.py`، والذي
يسجّل تلقائيًا الحرف الحقيقي المطلوب (الحقيقة الأرضية) مقابل تنبؤ النموذج —
بيانات دقة حقيقية قابلة للتحليل الإحصائي، لا مجرد ملاحظات يدوية.

---

## 1) قبل الجلسة: التجهيز

- تأكد إن التطبيق يعمل بشكل صحيح على الجهاز (راجع قسم Setup بـ`README.md`
  الرئيسي)، وإن نموذج تتبع اليد (`hand_landmarker.task`) موجود ومفعّل —
  الاختبار بدون تتبع يد حقيقي (مربع ثابت بالمنتصف) يقلّل الدقة بشكل مصطنع
  ولا يعكس أداء النظام الحقيقي.
- اختبر الإضاءة: إضاءة طبيعية أو صناعية معتدلة، بدون إضاءة خلفية قوية
  (نافذة مضيئة خلف المتطوع تُصعّب الرؤية).
- سجّل بيئة كل جلسة (إضاءة، نوع الكاميرا، المسافة التقريبية عن الكاميرا)
  بملاحظة نصية بسيطة — يفيد لاحقًا لو لوحظ تفاوت كبير بالنتائج بين
  المتطوعين.

## 2) نص الموافقة المسبقة (يُقرأ أو يُعرض على كل متطوع قبل البدء)

> "شكرًا لمشاركتك بتجربة نظام مساعد ترجمة لغة الإشارة العربية لأغراض بحثية.
> راح تُطلب منك تكرار حركة يد لكل حرف من حروف لغة الإشارة العربية (32
> حرفًا)، وتُسجَّل الكاميرا فيديو حي مؤقت لتحليله من قبل النظام فقط —
> **لا يُحفظ أي فيديو أو صورة لوجهك أو هويتك**، فقط نتيجة كل محاولة (الحرف
> المطلوب، تنبؤ النظام، ودرجة الثقة) تُخزَّن كرقم/نص لأغراض التحليل
> الإحصائي بالبحث العلمي. مشاركتك اختيارية بالكامل، ولك الحق تتوقف بأي
> وقت بدون أي سبب. هل توافق على المشاركة؟"

**ملاحظة مهمة:** الحقل `volunteer_id` بملف النتائج يُفترض يكون **رمزًا لا
اسمًا حقيقيًا** (مثلاً `V01`, `V02`, ...) — لا تكتب اسم المتطوع الحقيقي
بهذا الحقل، حفاظًا على خصوصيته حتى بالبيانات الخام المرفقة كملحق بالورقة
(لو قررتم إرفاقها).

## 3) خطوات الجلسة الفعلية (لكل متطوع، ~10-15 دقيقة)

1. افتح التطبيق، اضغط **"ابدأ الكاميرا"**، وتأكد رسالة الحالة تقول "النموذج
   جاهز (رمادي + ملوّن مدمج)" ورسالة الطرفية تؤكد "Real hand tracking
   active".
2. اضغط زر **"🧪 اختبار ميداني"**.
3. أدخل رمز المتطوع (مثلاً `V01`) بالنافذة المنبثقة.
4. سيعرض التطبيق تلقائيًا صورة الحرف المطلوب + اسمه، بترتيب عشوائي مختلف
   لكل متطوع (يمنع أي تأثير تعلّم/تعب منهجي على حرف بعينه عبر كل العينة).
5. اطلب من المتطوع يكوّن شكل اليد المطلوب **ويثبّته داخل المربع الملوّن**
   لمدة الدورة (ثانيتين) — النظام ينتقل تلقائيًا للحرف التالي بعدها بدون
   أي تدخل منك.
6. كرّر حتى تكتمل الـ32 حرف — التطبيق يعرض تلقائيًا رسالة ملخّص الدقة
   النهائية، ويحفظ ملف `field_test_results/V01_<تاريخ ووقت>.csv`.
7. كرّر الخطوات 2-6 لكل متطوع (رمز مختلف لكل واحد: `V01` إلى `V10`).

## 4) بعد جمع كل المتطوعين العشرة

انسخ كل ملفات CSV الناتجة (بمجلد `field_test_results/` بجذر المشروع) لمكان
واحد إن لم تكن مجتمعة أصلًا، ثم شغّل من جذر المشروع:

```bash
pip install matplotlib --break-system-packages   # إن لم تكن مثبَّتة أصلًا
python evaluation/analyze_field_test_results.py --results_dir field_test_results
```

هذا ينتج:
- `field_test_summary.txt` — الدقة الإجمالية، دقة كل متطوع على حدة، ودقة كل
  حرف عبر كل المتطوعين (يوضّح أي حروف أصعب على المستخدمين الجدد تحديدًا)
- `field_test_summary_confusion_matrix.png` — مصفوفة التباس حقيقية جاهزة
  لإدراجها بالورقة، بنفس أسلوب مصفوفات القسم 4.7 الحالية

## 5) كيف تُدرَج النتائج بالورقة

استبدل/أضف بالورقة (Section 4.6 والقسم المقابل بـSection 6):
- الرقم الإجمالي: "عبر 10 متطوعين (320 محاولة إجمالية)، بلغت الدقة الحية
  X%" -- بدل جملة "single-trial proof-of-concept" الحالية
- جدول دقة كل متطوع (من `field_test_summary.txt`) -- يوضّح التفاوت الفردي
  (إضاءة، خبرة سابقة، سرعة تعلّم الإشارات)
- مصفوفة الالتباس الجديدة كـ Figure إضافية
- مقارنة صريحة مع دقة التحقق المخبري (97.90% للفرع الملوّن، 96.56%
  للدمج، Section 4.7) -- أي فجوة بين الرقمين تُناقَش بصدق كنتيجة علمية
  حقيقية (فجوة نطاق بين ظروف المختبر والاستخدام الحي)، تمامًا بنفس
  أسلوب الورقة الحالي بمناقشة فجوة النطاق للفرع الرمادي

---

**ملاحظة تقنية:** آلية الاختبار الميداني (`start_field_test` بملف
`app/practice_session.py`) اختُبرت برمجيًا بمحاكاة كاملة (محاكي تنبؤ
مضبوط + محرّك أحداث Tkinter حقيقي)، وتأكَّد الربط الصحيح بين الحرف
المستهدف والتنبؤ المُسجَّل (دقة 32/32 مع محاكي "صحيح دائمًا")، وتأكَّد
تنسيق ملف CSV الناتج (يفتح بشكل صحيح بـExcel مع الحروف العربية). لم تُختبر
الدقة الفعلية بيد بشرية حقيقية بعد -- هذا بالضبط ما يوفّره هذا البروتوكول.
